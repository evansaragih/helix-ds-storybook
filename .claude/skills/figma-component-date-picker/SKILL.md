# Date Picker — Component Characteristics

Node `7188:4717` on the **Input Pickers** page (renamed from Date Pickers, id 1910:168), Nusantics Design System Figma file
(`GWzBKGr6512AeMOapwgQhj`). Companion to `figma-component-build` (general
build/audit rules) — this file is the per-component cheat sheet.

## What it is / when to use it

Date Picker is a calendar picker panel built on Content Container: shell chrome (surface, border, shadow) comes from the container, the calendar comes from _date-picker-base. Use for picking a single date, a week, a date range, or a date + time. Time only, month and quarter are separate component sets (Oct 31 2026 split, see "Split"): `Time Picker`, `Month Picker`, `Quarter Picker`, each with its own skill (`figma-component-time-picker`, `-month-picker`, `-quarter-picker`).

## Variant axes & properties

- `Mode` (Single, Week, Range, Date and Time)
- `Time Input` (None, Spinner, Dropdown)
- `State` (Closed, Open) on the wrapper

## Structure, tokens & known gotchas

Rebuilt Oct 2026 on Popover (replaced the Content Container version; node is now `8370:4116`, was `7188:4717`). Each variant = one `Popover` instance (`Trigger=Input+Label`, `Trigger Size=Small`, State Open/Closed) with `_date-picker-base` placed in `_popover-base`'s `Body Item List` slot. Axes: `Mode` x `Time Input` x `State` (Open, Closed). Slot overrides on the Open variants: strokes removed, padding bound to Spacing/12 (Single, Week, Range) or Spacing/0 (Date and Time, which carries its own Action row), slot width HUG so the panel hugs the calendar. Trigger Label/Placeholder text overridden per mode. Free layout: Closed row on top, Open row below, columns sized by panel width. The panel is absolute-positioned (static Y for the Small Input+Label trigger) and overflows the variant frame.

### Time input (Oct 2026)

The base set (7188:3069) is named `_picker-base` on the canvas (older text in this skill says `_date-picker-base`; same set). It is SHARED by Date, Time, Month, Quarter and Week Picker and was deliberately NOT split per picker. Axes `Mode` (Single, Range, Date and Time, Week, Time, Month, Quarter, Week List) + `Time Input` (None, Spinner, Dropdown, Columns) = 11 variants: Single/None, Week/None, Range/None, Range/Spinner, Range/Dropdown, Date and Time/Spinner, Date and Time/Dropdown, Time/Columns, Month/None, Quarter/None, Week List/None. Booleans `Show Seconds#8375:0` (default on, set by the designer), `Show AM/PM#8375:5` (default off), `Show Options#8383:0`, `Show Week Number#8404:8`. A Time-only Spinner/Dropdown was built then removed: it duplicated Date and Time minus the calendar; Date and Time carries a `Set Action` row (Now / Set) because it has two inputs (date + time) to confirm. Range with time (Oct 31 2026): `Range/Spinner` (8386:3720) and `Range/Dropdown` (8386:3855) = `Calendars` row (Start Month | End Month) + ONE `Time Range` strip (two groups "Start time" | "End time", each a time row cloned from the Date and Time `Action` row) + `Set Action` (Now/Set). The strip is one strip below both calendars, not one row per calendar, because the start date is not guaranteed to be in the left calendar. Show Seconds / Show AM/PM apply to both rows; Show Options opens the minute list under the Start minute only (Dropdown). Group rows need `layoutSizingVertical=HUG` after moving into the vertical group or they collapse to 1px. Wrapper `Date Picker` (8370:4116) is Mode x Time Input x State = 14 variants (one row of columns, 3132 wide; column x: Single 20, Week 344, Range 668, Range Spinner 1284, Range Dropdown 1900, Date and Time Spinner 2516, Date and Time Dropdown 2832); the booleans are NOT lifted to the wrapper (plugin API cannot forward nested props), they live on the nested `_date-picker-base` instance.
- Spinner = `Field` instances (Input Filled=True, trailing `li:chevrons-up-down`) joined by ":" texts. Dropdown = real `Select` instances (7793:7083, Open=False, Trigger=Input, Single, Filled=True), one per segment (`Select Hour/Minute/Second/AM PM`). Select's closed Input trigger has NO chevron, so each instance turns on `Show Trailing Content` on its nested Input and swaps the icon to `li:chevron-down` (4763:26984), an instance-level override that does not touch Select. Select is not Dropdown Menu (that one is Button-trigger action menus). Seconds field + second ":" and the AM/PM field (fixed 64 wide) are bound to the booleans; Fields are FILL width so two fields spread when seconds is off.
- The time-only Columns picker moved to `Time Picker` (see "Split").

### Split (Oct 31 2026)

The old `Period` axis (Day / Week / Quarter / Month) and `Mode=Time` were briefly in this set, then split by decision: Date Picker keeps Date and Time (time inside, Spinner / Dropdown), Week becomes `Mode=Week`; Time Columns, Month and Quarter became their own WRAPPER sets: `Time Picker` (8416:6688), `Month Picker` (8418:6821), `Quarter Picker` (8418:6841). They sit in a row below this wrapper on the Input Pickers page; each is `State` = Closed / Open only. The BASE was not split: all four wrappers nest variants of the one `_picker-base` set (`Mode=Time, Time Input=Columns`, `Mode=Month`, `Mode=Quarter`). I first made standalone per-picker bases by mistake (not asked for) and moved them back as variants. `Date Picker` had 0 instances elsewhere in the file, so nothing downstream broke. `_period-cell` (8402:69689) is shared by Month and Quarter.
- Split recipe (wrappers only): clone the wrapper Closed/Open variants, name `State=Closed` / `State=Open` and `figma.combineAsVariants`; the nested base instance in the Open clone's `Body Item List` slot already points at a `_picker-base` variant, just set its `Mode` / `Time Input` (or swap it to the right variant). If you ever swap or re-append a child in that slot, re-set the slot padding bindings afterwards (a new child can land 8px off until the `Spacing/*` binding is re-applied).
- Moving a standalone COMPONENT into a set (`set.appendChild`) keeps its existing instances; delete the component's own properties first and bind its layers to the set's property keys (a set's keys differ from the standalone ones).
- `Mode=Week` (base 7188 set, was `Period=Week`): the Single calendar with row 2 (4-10) in Range Start / In Range / Range End `_day` states, no new `_day` state. Boolean `Show Week Number#8404:8` (default off) shows a `Week Numbers` column (W header + W22-W26, text cloned from `_week-header` so the type tokens stay bound) in a `Week Body` row next to `Day Picker`; the month header is FILL so the panel goes 252 -> 288. The calendar is Su-first (as the rest of Day), so a week is Su-Sa, not Mo-Su; the week numbers are demo values.
- Week wrapper variants set `Mode=Week` on the nested base instance (Open one only); trigger reads Week / Select week (empty state, like the other modes).
- Build gotchas: `clone()` of a variant lands on the PAGE, not in the set, so `addComponentProperty` keys fail to bind ("Could not find a component property") until you `set.appendChild(clone)`; `findOne('_popover-trigger')` right after cloning a wrapper variant returns null (read it in a later call); a script that throws left no partial changes in this session, but still guard idempotent re-runs by checking for existing names.

- Gotchas: a visibility binding does not hide the layer in the master by itself, set `node.visible = false` on every bound layer (default off). `findAll` skips hidden layers, so make them visible temporarily before swapping nested icons. Cloned variants: `findOne` for the nested base can return null right after the clone, re-query in a later call. Rename variants in place (`Mode=X, Time Input=Y`) to keep instances.
- Open list of the Dropdown style is built into the component: boolean `Show Options#8383:0` (default off) on `_date-picker-base`, bound to the `Options List` layer (8383:4147) in the Dropdown variant (8375:3147). It is an ABSOLUTE `_popover-base` instance (88 wide, below `Select Minute`, `Body Item List` slot = List Items 29-34, `Show Leading` off, row 2 Active with check). It only shows on the Minute segment (a per-segment picker would need another property). The list pops out of the panel because `clipsContent=false` on the variant and on the wrapper's `Body Item List` slot (Dropdown Open variant 8375:3821).
- **Slot edits leak to the master:** `swapComponent` on a node inside slot content of an INSTANCE (e.g. swapping `Select Minute` inside a temp instance of the wrapper variant) changed the shared master of `_date-picker-base` and the wrapper variant, not just the instance. Never use a temp instance to test a swap; do it on a throwaway clone of the component, or swap back after. After any experiment, verify the nested `Select *` mains are all `Open=False`.
- **Z-order trap:** these variants have `itemReverseZIndex = true` (first child on top). A new overlay child must be `insertChild(0, ...)`, not appended, or it renders under the calendar. A hidden instance (visible=false) exposes no children; toggle it visible to edit its slot. A SLOT inside an instance whose content is HUG needs the slot set to FILL before resizing the instance, or the content keeps its old width.

### Calendar parts (all underscore-prefixed = internal, not published)

`_month-header` (88:6698), `_week-header` (88:6714), `_week-days` (88:6824), `_day` (88:6841). Consolidated Oct 2026: the old single-date `Day` / `Week Days` and the unused `Range Month Header` were deleted; the former `Range Day` / `Range Week Days` became `_day` / `_week-days`. `_day` has ONE variant axis, `State` (9 values): Default, Hover, Today, Outside, Outside Hover, Selected, Range Start, In Range, Range End (+ single-valued `Appearance`). Merged from 18 variants (4 axes) in Oct 2026 after a visual-signature check showed only 8 unique looks. Done in place: re-pointed the 28 nested Outside-Day range cells to In Range, deleted 9 zero-instance duplicates, renamed the rest; instance counts per variant were identical before/after. Today HAS its own design (checked 2026-11-26, the earlier note that it matched Hover was wrong): inner `Button` fill #FEF2E9 (status-brand-bg), text #14141E, radius 6. The set uses free layout (layoutMode NONE) - in GRID mode child x/y is ignored and anchors are read-only on components.

### Gotchas (hard-won)

- **Swapping a nested instance inside a MASTER wipes every downstream instance's per-cell overrides.** Swapping `Day` -> `Range Day` inside the old `Week Days` master reset all dates/states in every `Week Days` instance (digits back to 1..7, no selected/today/outside). Reads of `characters` afterwards return the already-reset values, so they cannot be used as a backup. Record cell state BEFORE any master-level swap, or avoid it.
- `swapComponent` on a top-level `Week Days` instance also drops its nested cell overrides; reapply per cell with `setProperties` after swapping.
- After `setProperties` changes a cell's Variant/isSelected, a stale text-fill override can stay on the cell (selected cell rendered dark text). Resync: `text.fills = mainComponent's text.fills`.
- June 2026 demo pattern: row0 = 28,29,30,31 (Outside Day),1,2,3; row1 = 4..10 with 7 selected; row4 = 25,26,27,28 (Today),29,30,1 (Outside Day).
- **Never findAll TEXT by name across a whole variant to rename the trigger placeholder.** Nested calendar texts share the name `Placeholder` (month/year dropdowns, Time's Now/Set buttons) and get overwritten too; scope to the trigger (`_popover-trigger`) instead. Fixed once: month/year restored to June / 2026, buttons to Now / Set.
- Legacy `_calendar`, `_range-calendar`, `Date Picker / Basic`, `DateTime Picker / Basic`, `Time Picker / Basic`, `Date Picker / Date Picker Range` were deleted (all unused outside each other).
- Resolved by Oct 30-31 2026 (checked by screenshot): the "Button" year label, the Range second-month chevron (header 1 has only chevron-left, header 2 only chevron-right, no overlap), the Date and Time Action row overflow, and the Time Action row covering the list.
- Open: `_day` has no Disabled state (only Outside), while code has `isDisabled` (opacity 0.4), so a disabled day has no Figma counterpart; `_day` State=Outside Hover reads fill #FFE1C9 with text #14141E, which does not look like an outside-day hover (ask the designer before relying on it); the Open trigger (240, no chevron, focus style) differs from Closed (180, chevron) because it is inherited from Popover.

### Measured geometry and state styles (2026-11-26)

Read straight from the Open variants, for checking code against Figma:
- **Shell:** `_popover-base` 284 wide for Single, fill #F7F7F7 (variable bound), radius 12, padding 4, stroke #EEEEEE, 2 shadows; `Body Item List` slot 276 (padding 12); `_picker-base` 252. Range is 552 / 520 (252 + 16 + 252).
- **Header:** `_month-header` 252 x 36. Single: prev at x=0, next at x=223, the two dropdowns (84 x 36, gap 10, month shows the full name, e.g. "June") centred. Range: the Start header has only prev (dropdowns at x=37 and x=150), the End header has only next (dropdowns at x=0 and x=112). Icon Button 29.33 square, radius 5.33, fill #FFFFFF, stroke #EEEEEE.
- **Calendar:** `_week-header` 20 tall (y=52), 13px Regular #828282; day rows 36 tall, pitch 44, first row y=80; `Day Picker` frame is 272 tall (16 below the grid).
- **`_day` text:** every state is 13px Regular, line-height 19.2, letter-spacing -0.01. Default #49494A, Outside #9F9F9F, Selected #FAFAFA on a `Button` fill #F57E20 radius 6, Today #14141E on #FEF2E9 radius 6, In Range fill #FEF2E9, Range Start / End fill #F57E20 text #FFFFFF.
- **Date and Time:** `Action` (time row) 60 tall, padding 12 top and bottom, top hairline #EEEEEE, fields 71 wide (FILL); `Set Action` 52 tall, padding 8, space-between, `Button` Now (51 wide) and Set (45 wide), top hairline. Base 420 tall for a 5-row month.
- **Range with time:** `Time Range` strip 84 tall (padding 12, gap 16, top hairline) with two groups of 252: a 13px #49494A label ("Start time" / "End time"), gap 4, then the 36px time row; then `Set Action`. Base 472 tall.
- **Week:** Mode=Week shows the Single calendar with a week row in Range Start / In Range / Range End.
