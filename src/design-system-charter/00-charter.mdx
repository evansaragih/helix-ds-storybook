## Why this exists

We run two generations of UI libraries and one Figma library. Designers and engineers describe the same
component with different names, different variants and different tokens. This charter defines the shared
language so that:

1. Every foundation, token and component means exactly one thing in Figma, in code, and in Storybook.
2. A designer and an engineer can hand work to each other without a meeting.
3. An AI agent can resolve "which component is this?" deterministically, not by guessing.

## The rule behind every rule

> **A convention only exists if something enforces it.**

Every section names both the **rule** and the **mechanism** — a lint rule, a hook, a generator, a skill, a
review gate. A rule with no mechanism is a wish, and we do not write wishes down here.

Enforcement runs **locally** — eslint, the pre-push hook, and skills invoked on demand. We do not push
routine checks into CI.

## Roles

| Role | Accountable for |
|---|---|
| **DS Design Owner** | Figma library: component set structure, variant properties, tokens, descriptions |
| **DS Engineering Owner** | Code library: public API, DoD enforcement, release, codemods |
| **Contributors** | Follow the DoD; raise an RFC when a rule blocks them |

Ties are broken by the two owners jointly. If they cannot agree, the default written in this charter wins and
the disagreement becomes an RFC.

## Scope

Governs `@nusantics/ui-kit/design-system` and `@nusantics/ui-kit/ui-tokens`.
Companion libraries (`charts-plotly`, `maps`, `pdf-preview`) follow §1 (tokens) and §6 (DoD) but keep their
own APIs — the DS references them, it does not absorb them.
